## 中国大陆三网：电信移动正常，联通绕欧洲

三网平均延迟（第三方实测，大阪节点）：电信约 70ms，移动约 91ms，联通约 269ms。

差距来自路由。电信去程走 163 骨干网出境，接入 SoftBank（AS17676），经东京落地大阪；移动去程走 CMI 到香港，再转 SoftBank 进大阪；联通去程走 AS4837 出境后绕道法兰克福、巴黎、伦敦，再跨美洲到日本，绕了半个地球。

回程三网统一走 SoftBank，再分别接回 163、4837、CMI。所以这套方案的实质是 SoftBank 回程，电信和移动体验好，联通从去程就开始跑偏。

联通用户买这台机器，269ms 的平均延迟会把 SSH、面板、网页加载全部拖慢，价格再低也不值得。电信和移动用户则相反，70ms 和 91ms 在非 CN2 线路里属于不错的水平，港澳台方向也在 51–57ms，日本境内互 ping 8ms 上下，做面向东亚的小型游戏服或者低延迟中转站是够的。

需要说清楚的是，大阪用的是标准国际路由，不是 CN2、9929、CMI 这类中国大陆优化专线。如果你的业务对大陆访问质量有硬性要求，得另找走优化线路的节点，别指望这台机器通过调优变成 CN2。
